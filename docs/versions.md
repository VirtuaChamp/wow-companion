## TS runner for `scripts/*.ts` (revised round 2, PM decision 2026-09-27)

Plain `node`, no package. Round 1 chose `tsx` over `ts-node` and bare `node --experimental-strip-types`. Round 2 re-tested `node` on this machine (`node --version` → `24.12.0`, no flags): a relative import ending `.ts` resolved and ran without error, and a file using a `enum` (non-erasable TS syntax) failed with `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` — i.e. Node's built-in type-stripping already enforces exactly the "erasable TypeScript only" rule `tsconfig.base.json`'s new `erasableSyntaxOnly` flag also enforces, no experimental flag needed on Node 24. Since the apps and scripts run directly on Node's native stripping with no build step, `tsx` added an unused indirection: dropped from the catalog and from every `package.json`. Root scripts now call `node scripts/*.ts` directly; `apps/companion/src/main.ts` and `apps/mcp/src/server.ts` run as `node apps/*/src/*.ts` (root scripts `start`, `mcp`). Type checking (not enforced by `node` itself) still runs through `tsc -b` via `tsconfig.tools.json` and each workspace tsconfig, per round 1.
