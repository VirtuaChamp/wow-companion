## Chat window and edit box (09)

- No untainted hook exists on any Blizzard-owned chat edit box for `/r` routing or Tab-accept of `@` ghost text (full citation trail in this slice's `HANDOFF-INTENT.md`, first round). User decision 2026-09-27: the Claude window owns its own addon-created edit box instead; nothing in this slice calls `SetScript`/`HookScript` on a Blizzard-owned edit box, and `/r` is never read or redirected anywhere in `addon/`.
- Window chrome: `CreateFrame("Frame", name, UIParent, "ButtonFrameTemplate")` — `ButtonFrameTemplate` inherits `ButtonFrameBaseTemplate` inherits `PortraitFrameBaseTemplate` (mixin `PortraitFrameMixin`), giving a title region (`TitleContainer.TitleText`, `Interface/AddOns/Blizzard_SharedXML/Mainline/SharedUIPanelTemplates.xml:598-610`), close button and standard Blizzard dialog art with no custom texture — same file, lines 566-709. The window's title is set through that template's own `TitleContainer.TitleText:SetText("Claude")`, not a second hand-built FontString. The window is a plain addon-owned `Frame` parented to `UIParent`, not a member of the Blizzard `FCF_*` floating-chat-frame pool (`FCF_OpenNewWindow`/`FCF_OpenTemporaryWindow`, `Interface/AddOns/Blizzard_ChatFrameBase/Mainline/FloatingChatFrame.lua:801,976`) — using that pool would tie the window into Blizzard's own chat-type/whisper-target system, the exact taint the first builder round found and the user's 2026-09-27 decision avoids. Movable/resizable/clamped via `SetMovable`, `SetResizable`, `SetClampedToScreen`, `SetResizeBounds`, `RegisterForDrag("LeftButton")` plus `OnDragStart`/`OnDragStop` (`StartMoving`/`StopMovingOrSizing`) — the same generic frame-drag pattern Blizzard's own movable dialogs use, e.g. `OnDragStart`/`OnDragStop` methods declared on `Interface/AddOns/Blizzard_SharedXML/Mainline/SharedUIPanelTemplates.xml:1637-1659`. Resizing is a second, addon-owned `Button` anchored at the window's `BOTTOMRIGHT`, whose `OnMouseDown`/`OnMouseUp` call `frame:StartSizing("BOTTOMRIGHT")`/`frame:StopMovingOrSizing()` — the same two calls Blizzard's own resizable dialogs pair (e.g. `ClassTrainerFrame`'s resize button), no custom sizing math. Position and size are kept in `WoWCompanionDB.window` (point, relativePoint, x, y, width, height) and restored on the next `ADDON_LOADED`, so the window is created once and never recreated on `/reload` (`ns.AiWindow.create()` is idempotent). The gear button is a plain `CreateFrame("Button", ...)` with a text-label `FontString` ("⚙") rather than a Blizzard atlas texture — no settings/gear atlas name could be confirmed against this clone's XML/Lua sources (only texture _files_, not atlas _names_, are absent from this repo), so a literal atlas string was not fabricated; sized 20x20 with a `GameTooltip` "Settings" tooltip on `OnEnter`/`OnLeave`. Unverified in client; flag to the PM if a specific atlas is wanted.
- Message log: `CreateFrame("ScrollingMessageFrame", name, parent)` — the same native widget type Blizzard's own chat frames use (`ChatFrameTemplate` inherits `ScrollingMessageFrame`, `Interface/AddOns/Blizzard_ChatFrameBase/Mainline/ChatFrame.xml:3`); this addon creates a bare `ScrollingMessageFrame` directly rather than inheriting `ChatFrameTemplate`, since that template's `mixin="ChatFrameMixin"` wires real `CHAT_MSG_*` event handling this window must not carry. `AddMessage(text, r, g, b)` is called with `NORMAL_FONT_COLOR:GetRGB()` (reply/echo lines), `GRAY_FONT_COLOR:GetRGB()` (status lines: progress, errors, waypoint, help, the off-screen-reply notice) or `YELLOW_FONT_COLOR:GetRGB()` (`ns.AiWindow.notice`, the single Blizzard-system-coloured line slice 10 calls for provider/model switches) — Blizzard colour constants, no numeric literal. `scrollFrame:SetHyperlinksEnabled(true)` plus an `OnHyperlinkClick` script calling the global `SetItemRef(link, text, button, self)` is required for `[more]`/`[open]` clicks to reach `SetItemRef` at all; only `ChatFrameMixin:OnHyperlinkClick` (a template this window does not inherit) wires that call for Blizzard's own chat frames — `Interface/AddOns/Blizzard_ChatFrameBase/Shared/ChatFrame.lua:19-24`.
- Input line: `CreateFrame("EditBox", name, parent, "InputBoxTemplate")` — `InputBoxTemplate` is a generic, non-chat edit box template used across many unrelated Blizzard panels (search boxes, dialogs) — declared `Interface/AddOns/Blizzard_SharedXML/Shared/InputBox/InputBoxTemplates.xml:70`, inheriting `InputBoxScriptTemplate`. Its key scripts are ordinary `EditBox` widget scripts, not chat-specific: `OnEnterPressed`, `OnTabPressed`, `OnEscapePressed` are used the same way on non-chat edit boxes such as the Auction House search bar (`Interface/AddOns/Blizzard_AuctionHouseUI/Shared/Blizzard_AuctionHouseSearchBar.xml:7`) and the in-game AutoComplete edit box (`Interface/AddOns/Blizzard_AutoComplete/AutoComplete.xml:5-6`); `OnArrowPressed` likewise fires on ordinary search-box edit boxes, e.g. `Interface/AddOns/Blizzard_GroupFinder/Mainline/LFGList.xml:1077`, not only on the chat edit box. Because this addon creates its own `EditBox` from this generic template, `SetScript` on it is not a hook on any Blizzard-owned edit box.
- `@` popup and ghost text: implemented entirely on this addon-owned input line, driven by `ns.Mention.match`/`ns.Mention.candidates` (slice 07); popup rows are `CreateFontString(nil, "OVERLAY", "GameFontHighlightSmall")` on a `CreateFrame("Frame", name, parent, "TooltipBackdropTemplate")` backdrop (Blizzard tooltip-style backdrop template, no custom texture), anchored above the input line (`popupFrame:SetPoint("BOTTOMLEFT", inputBox, "TOPLEFT", 0, 4)`) with each of the 8 rows stacked `TOPLEFT`-to-`BOTTOMLEFT` under the previous one; the selected row is coloured with `HIGHLIGHT_FONT_COLOR:GetRGB()`, the rest with `NORMAL_FONT_COLOR:GetRGB()`; the ghost text is a further `GameFontDisable` FontString anchored above the popup. Same ghost/Tab-accept path also completes `/ai` sub-commands (`new`, `chat`, `settings`, `report`, `reset`, `cancel`, `help`, `context`) when the input line reads `/ai <partial>`, but only routes to the sub-command handler through `Core.handleAi` when the accepted line matches `^/ai%s`; typing `help`/`context`/`settings`/`report`/`reset`/`cancel` with trailing text after it falls through to a plain ask instead (matches "spending" like `/ai help me find Hogger` is a question, not the help command).
- `/ai <text>` from any chat box: registered the plain way every addon slash command is, `_G.SLASH_AI1 = "/ai"` then `_G.SlashCmdList["AI"] = handler` (the `_G.` indirection is this addon's own choice to satisfy `luacheck`'s frozen `.luacheckrc`, not a client requirement); `SlashCmdList`/`hash_SlashCmdList` is a normal, unrestricted extension point that Blizzard's own `/r` handling never reaches (confirmed in this slice's first round: `HandleChatType`'s `REPLY` branch returns before `hash_SlashCmdList` is consulted, `Interface/AddOns/Blizzard_ChatFrameBase/Mainline/ChatFrameEditBox.lua:256` vs `:265`), so registering `/ai` cannot collide with or intercept `/r`.
- `[more]`/`[open]` links: built with the Blizzard-registered `addon` hyperlink link type, namespaced by the addon name so no other addon's `addon:` link can open this window's box and vice versa: `LinkUtil.FormatLink(LinkTypes.AddOn, "[more]", "WoWCompanion", "more", id)` (`Interface/AddOns/Blizzard_SharedXML/LinkUtil.lua:69-77`) produces `|Haddon:WoWCompanion:more:<id>|h[more]|h`. Clicking calls the global `SetItemRef(link, text, button, frame)` (`Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ItemRef.lua:6`), which calls `LinkUtil.ProcessLink` → `SplitLinkData` (same file, lines 79-83) to strip the `|H`/`|h` wrapper before invoking the per-type handler, so the handler only ever sees the bare `addon:WoWCompanion:more:<id>` string, never the escape sequence. `LinkUtil.RegisterLinkHandler(LinkTypes.AddOn, function(link, text, linkData, contextData) EventRegistry:TriggerEvent("SetItemRef", link, text, contextData.button, contextData.frame) end)` is already registered by Blizzard itself for the `addon` type — `Interface/AddOns/Blizzard_UIPanels_Game/Shared/ItemRefHandlersShared.lua:279-283` — so this addon never calls `LinkUtil.RegisterLinkHandler`/`hooksecurefunc("SetItemRef", ...)` itself (either would be a second registration or a global hook); it only calls `EventRegistry:RegisterCallback("SetItemRef", handler, owner)` to listen for the event Blizzard fires, then parses the bare link with `LinkUtil.SplitLinkData` plus `strsplit(":", linkOptions)` to recover the addon name, kind (`more`/`open`) and id.
- `ChatFrameUtil` is not used anywhere in this slice. The names investigated in round 1 (`ChatFrameUtil.GetLastTellTarget`/`SetLastTellTarget`/`GetNextTellTarget`, `Interface/AddOns/Blizzard_ChatFrameBase/Mainline/ChatFrameUtil.lua:620-627`) belong to Blizzard's own `/r`-target tracking, which the user's 2026-09-27 decision avoids entirely by keeping `/r` untouched and giving the Claude window its own input line; none of them are read or called from `addon/`.
- Chats dropdown (D11): `CreateFrame("DropdownButton", name, parent, "WowStyle1DropdownTemplate")` then `dropdown:SetupMenu(function(dropdown, rootDescription) rootDescription:CreateButton(text, onClick) ... end)` — the exact pattern shown in Blizzard's own menu implementation guide, `Interface/AddOns/Blizzard_Menu/11_0_0_MenuImplementationGuide.lua:107` (widget type), and used the same way by real dropdowns such as `Interface/AddOns/Blizzard_AddOnList/AddonList.lua:642`. Entries sort by `lastAt` descending and each label carries the chat name, provider and a relative age (`Xs`/`Xm`/`Xh`/`Xd` from `time()`), a running marker and an unread count. Rename and Delete are two further `CreateButton` entries per chat (this widget's `SetupMenu` has no documented right-click-specific submenu in the sources checked, so both actions are reachable from the same left-click menu rather than an unverified right-click gesture — flagged to the PM); each confirms through `StaticPopupDialogs["WOWCOMPANION_RENAME_CHAT"|"WOWCOMPANION_DELETE_CHAT"]` and `StaticPopup_Show(...)`, the standard Blizzard confirm-dialog API, before sending the `rename`/`delete` command.
- No `SetScript`/hook of any kind on `ChatFrame1EditBox` or any other Blizzard-owned edit box exists in `addon/`; `pnpm run guard`'s "no deprecated chat globals" rule (zero `ChatFrame_AddMessageEventFilter`/`ChatEdit_`/`ChatFrame_ReplyTell` in `addon/`) and a full-repo grep for `SetScript` confirm every `SetScript` call in this slice targets a frame this addon itself created via `CreateFrame`.
