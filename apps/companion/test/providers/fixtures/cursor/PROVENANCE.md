**Privacy fix, round 4b.** The first `session_unknown.jsonl` recording (prompt `"continue"`) had the model explore the repo and hit blocked shell hooks, and its tool-call output carried the operator's Windows home path (drive letter, `Users`, JSON-escaped backslash separators) and other forms. The recorder's `redact()` only matched a single literal separator character, so the JSON-escaped double-backslash form passed through uncaught — a real leak in the previously committed fixture, since fixed and the file re-sanitized in place (no rerun): `redact()` now matches one or two escaped separator characters for the Windows form, plus the mac equivalent, and a dedicated pass that redacts the operator's own `os.userInfo().username` wherever it appears standalone. `fixtures.privacy.test.ts` extended to scan for both separator counts and the machine's live username, not a hardcoded one.

`--workspace` stays in `cursorArgs()` regardless of the confirmed-not-working result — harmless, and the right shape if a later cursor version honours a per-run project MCP config. Root cause of the discovery failure (whether it's the `--workspace` value, the `.cursor/mcp.json` location, or something else) was not pursued further per the PM's decision to close this as v1's final answer for cursor.
